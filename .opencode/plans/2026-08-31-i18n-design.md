# Internationalization (i18n) Design Spec

## Overview

Add English internationalization to the portfolio application using react-i18next with automatic language detection. The application will detect the user's browser language and display content in the appropriate language (Portuguese or English).

## Decisions

- **Language switching**: Automatic detection via `navigator.language` (no manual toggle)
- **Translation library**: react-i18next with i18next
- **File organization**: Separate folders per language (`src/data/pt/` and `src/data/en/`)
- **Default language**: Portuguese (pt)
- **Fallback**: If detected language is not supported, fallback to Portuguese

## 1. Configuration (react-i18next)

### New file: `src/i18n.ts`

```typescript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

// Translation resources will be imported here
import pt from './data/pt/translation.json';
import en from './data/en/translation.json';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      pt: { translation: pt },
      en: { translation: en }
    },
    fallbackLng: 'pt',
    interpolation: {
      escapeValue: false
    }
  });

export default i18n;
```

### Modified file: `src/main.tsx`

Add import at the top:
```typescript
import './i18n';
```

### Translation resource strategy

We have two options:

**Option A: Single merged file (recommended)**
- Create `src/data/pt/translation.json` and `src/data/en/translation.json` that merge all section JSONs
- Import the single file in `src/i18n.ts`
- Simpler configuration, single import

**Option B: Separate imports merged in config**
- Keep individual JSONs (header.json, hero.json, etc.)
- Import all and merge in `src/i18n.ts`:
  ```typescript
  import headerPt from './data/pt/header.json';
  import heroPt from './data/pt/hero.json';
  // ...
  const pt = { header: headerPt, hero: heroPt, ... };
  ```
- More granular files but more imports

**Decision**: Option A (single merged file) for simplicity.

## 3. Component Translation

Each component will be updated to use the `useTranslation` hook:

### Before (example - Hero.tsx)

```tsx
import heroData from '../data/hero.json';

export function Hero() {
  return (
    <h1>{heroData.greeting}</h1>
  );
}
```

### After

```tsx
import { useTranslation } from 'react-i18next';

export function Hero() {
  const { t } = useTranslation();
  return (
    <h1>{t('hero.greeting')}</h1>
  );
}
```

### Components to update

- `Header.tsx`
- `Hero.tsx`
- `About.tsx`
- `SkillsWrapper.tsx`
- `Experience.tsx`
- `Contact.tsx`

## 5. SEO and Meta Tags

### index.html

- Keep meta tags in Portuguese as fallback
- Update `lang` attribute dynamically via JavaScript
- Add hreflang links:
  ```html
  <link rel="alternate" hreflang="pt" href="/?lang=pt">
  <link rel="alternate" hreflang="en" href="/?lang=en">
  ```

### Dynamic updates via JavaScript

- Create `src/hooks/useDocumentLang.ts` hook to update `document.documentElement.lang`
- Use `useEffect` to update `<title>` and `<meta description>` when language changes
- Hook will be used in `App.tsx` to apply language changes globally

### Open Graph tags

- Keep OG tags fixed in Portuguese (indexed by crawlers that don't execute JS)
- Full SEO would require SSR/SSG (out of scope)

## Scope

### In scope

- English translation of all user-facing text
- Automatic language detection
- Component updates to use i18n
- Hardcoded string translation
- Basic SEO updates

### Out of scope

- Manual language toggle button
- Full SEO with SSR/SSG
- Date/number formatting by locale
- Image/content translation
- Pluralization rules
